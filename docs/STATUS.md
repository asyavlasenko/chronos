# Chronos — стан проєкту

Оновлено: 2026-11-16. Чекліст вимог ТЗ лежить у [00-cbl-progress.md](00-cbl-progress.md), контракт API в [api.md](api.md).

## Зроблено

### Інфраструктура
- [x] Монорепо `backend/` + `frontend/`, ESLint (Airbnb) і Prettier в обох частинах.
- [x] Dockerfile для backend (dev і production стадії, non-root) і frontend (Vite build, потім nginx з проксі `/api`).
- [x] `docker-compose.yml` (mongo + backend + frontend з healthcheck-ами) і `docker-compose.dev.yml` (hot reload).
- [x] `docker compose up --build` перевірено: усі сервіси здорові, наскрізний сценарій API через nginx проходить.
- [x] Seed демо-даних: `npm run seed` у `backend/` (три користувачі, спільний календар, тиждень подій).

### Backend
- [x] **auth**: реєстрація зі створенням головного календаря і підтвердженням email за посиланням із листа, вхід (закритий до підтвердження), оновлення сесії (refresh у httpOnly cookie), вихід, скидання пароля листом.
- [x] **users**: профіль (ім'я, фото), налаштування календаря і сповіщень, зміна пароля, вихід з усіх пристроїв.
- [x] **calendars**: CRUD, приховування і власний колір для кожного учасника, спільний доступ із ролями owner/editor/viewer, вихід з календаря, скасування запрошень. Головний календар не видаляється, не ховається і не стає спільним.
- [x] **events**: три типи (arrangement, reminder, task), обов'язкова дата в кожної події, тривалість зустрічі за замовчуванням із профілю, вибірка за діапазоном, фільтри за календарями й типами, пошук, учасники, права редактора і власника.
- [x] **нагадування**: планувальник раз на хвилину надсилає лист за N хвилин до події авторові й учасникам, кожному в його часовому поясі; «не нагадувати» для окремої події.
- [x] **сповіщення**: листи учасникам про перенесення, зміну місця і скасування події; перемикачі сповіщень у профілі справді вмикають і вимикають листи.
- [x] **invites**: запрошення на подію і в календар по email, публічний перегляд за посиланням, прийняти або відхилити, термін 7 днів.
- [x] **holidays**: державні свята з Nager.Date, кеш у MongoDB за країною і роком, застарілий кеш при недоступності сервісу.
- [x] Пошта через nodemailer і Ethereal: без налаштувань бекенд сам створює тестову скриньку і друкує посилання на перегляд листа.
- [x] Валідація всіх вхідних даних (Joi) з повідомленнями українською, єдиний формат помилок.
- [x] Стійкість: обмеження спроб входу, реєстрації та скидання пароля (429), захист від одночасної зміни учасників події (409), тести на зіпсовані запити.
- [x] **плаваючі задачі**: справи без дедлайну (`isFloating`), датою в базі стає момент створення; не показуються в календарі й не нагадують.
- [x] **drawings**: зберігання малюнків з дошки, штрихи прив'язані до часу, а не до пікселів.
- [x] Список схованих блоків головного екрана зберігається в профілі.
- [x] **assistant**: помічник на Claude перетворює фразу на чернетку події (`POST /assistant/draft`); без ключа вимкнений.
- [x] **telegram**: бот (`node-telegram-bot-api`) дублює нагадування в особистий чат; чат підключається одноразовим посиланням із профілю; без токена вимкнений. Повідомлення з HTML-оформленням і кнопками «Відкласти на 10 хв» та «Виконано», команди `/today`, `/tomorrow`, `/help`, `/stop`; опис і меню команд бот виставляє сам. `/today` і `/tomorrow` відповідають HTML-віджетом (Bot API 10.4) з перемикачем дня й чекбоксами задач, текстовий список лишається запасним варіантом.
- [x] 365 тестів (Jest + supertest) проти справжньої MongoDB; тести помічника не звертаються до справжньої моделі.

### Frontend
- [x] Усі 16 екранів з `design/screens`, UI-кит, мобільна версія.
- [x] Працює на справжньому API: вхід, реєстрація, скидання пароля, профіль, календарі, події, задачі, запрошення, свята.
- [x] Під час реєстрації часовий пояс і країна (для свят) визначаються з браузера.
- [x] **Головний екран це дошка**: горизонтальне полотно на 14 днів із подіями-наклейками, масштаб, прокрутка, лінія «зараз».
- [x] Нову подію можна намалювати мишкою на дошці (рамка з кроком 15 хвилин і поле для назви), створити через «+» або повну форму.
- [x] Блок «Колись» із плаваючими задачами; задачу можна перетягнути на дошку, щоб призначити їй час.
- [x] Модульні блоки під дошкою: кожен можна сховати хрестиком або в «Налаштувати».
- [x] Малювання на дошці мишею, пальцем або стилусом: шість кольорів, три товщини, гумка, скасування, очищення.
- [x] **Помічник: 3D-лінивець** у кутку екрана (зібраний із фігур у коді, без сторонніх моделей). Пишеш фразу («завтра о 15 нарада на годину»), він неквапом ходить убік, поки думає, потім іде «на календар», повзе по драбинці нагору і створює подію; її можна одразу відкрити або скасувати. Без ключа Claude API лінивця немає.
- [x] Два способи створення події: модалка по кліку на слот і окрема сторінка. Клік по події відкриває деталі.
- [x] Подання день, тиждень (картки і стрічка часу), місяць, рік; номери тижнів ISO 8601.
- [x] Права в інтерфейсі: редагування й видалення видно лише тим, кому це дозволено.
- [x] Стани завантаження й помилок, сповіщення про результат дій.
- [x] Власна сторінка для неочікуваних помилок інтерфейсу: застосунок не показує «сирий» збій.
- [x] **Теми оформлення:** вісім кольорових тем у світлому й темному варіантах плюс режим «як у системі»; вибір у профілі, зберігається в акаунті.
- [x] Стилі приведено до Google HTML/CSS Style Guide (класи через дефіс, кольори малими літерами, порожній рядок між правилами).

### Відомі обмеження
- Фронт завантажує всі події користувача одним запитом і фільтрує їх у браузері. Серверні фільтри за діапазоном, типами й пошуком реалізовані й протестовані, але інтерфейс поки ними не користується. Для великих обсягів варто перейти на завантаження за діапазоном подання.
- Події, що перетинаються в часі, малюються одна поверх одної, без розкладки в колонки.
- Вхід через Google і push-сповіщення в браузері не реалізовані; їхні кнопки-заглушки з інтерфейсу прибрано.
- Фото профілю зберігається прямо в документі користувача (стиснуте до 256 px) і показується в профілі та шапці; в учасників спільних календарів і далі видно ініціали.
- Нагадування надходить листом і, якщо підключено, повідомленням у Telegram; якщо надіслати не вдалося, повторної спроби немає.
- Telegram-бот отримує оновлення через long polling, тому з одним токеном має працювати лише одна копія сервера.
- HTML-віджети Telegram з'явились 9 листопада 2026, але з 13 листопада Telegram закрив їх для звичайних ботів: `sendWidget` відповідає `INPUT_MEDIA_WIDGET_NOT_ALLOWED` (підтверджено в tdlib/telegram-bot-api, issue 947). Тому зараз `/today` і `/tomorrow` приходять текстом. Код віджета лишається: щойно Telegram відкриє доступ, бот почне надсилати його сам. У справжньому чаті віджет не перевірено.
- Кнопка «Відкрити подію» в Telegram з'являється лише коли сайт працює на `https://`; сторінки всередині Telegram (Mini Apps) не реалізовані, бо їм теж потрібна публічна адреса.
- Обмеження спроб входу зберігається в пам'яті одного процесу: після перезапуску сервера лічильники обнуляються.
- Для дошки, наклейок і малювання мокапів у `design/` немає: це рішення команди від 2026-11-16, зроблене поверх наявних токенів.
- Дошка доступна від 768px; на телефоні головний екран лишився списком дня, малювання там немає.
- Малювати можна лише на дошці, не на інших екранах. Малюнки особисті, у спільних календарях інші їх не бачать.
- Помічник виконує одну команду за раз і не пам'ятає попередніх: це не чат. Він уміє лише створювати події, змінювати й видаляти не вміє.
- Промокредити Claude API діють до 4 грудня 2026; після цього помічник працюватиме лише з платним ключем.
- Формат часу 12 год із профілю враховується не в усіх місцях.
