### Чеклист Basic (з ТЗ)

- [ ] Реєстрація, вхід, вихід, скидання пароля
- [ ] Головний календар створюється автоматично; не видаляється й не ховається
- [ ] Додаткові календарі: назва, опис, колір; редагуються, ховаються, видаляються
- [ ] Вбудований календар державних свят за країною з профілю (зовнішній API, кеш по країні+року)
- [ ] Події трьох типів: arrangement (початок/кінець, дефолтна тривалість), reminder, task (виконано)
- [ ] Обов'язкові поля події: назва, дата, календар
- [ ] Два способи створення: клік на порожнє місце (без переходу) і кнопка (окрема сторінка)
- [ ] Запрошення на подію по email
- [ ] Спільні календарі: кілька користувачів створюють події в одному календарі
- [ ] Кожен учасник обирає колір своїх подій; права owner/editor/viewer
- [ ] Подання тиждень / місяць / рік; номери тижнів у тижневому поданні
- [ ] Фільтр за категоріями (календарями/типами), пошук
- [ ] Усі події клікабельні з прев'ю; відображення відповідно до тривалості
- [ ] Прості форми створення; валідація всіх полів з повідомленнями
- [ ] Адаптивність (mobile, tablet)
- [ ] Сервіс не падає (обробка всіх помилок)
- [ ] Docker: окремі контейнери для backend і frontend, docker-compose з базою, змінні середовища

**Що зроблено по тижнях:**
- 2026-11-06 — каркас репозиторію (backend + frontend + Docker + docs). Фронтенд зверстано за всіма 16 мокапами
  на мок-даних (`frontend/src/mocks/data.js`): усі подання календаря, задачі, календарі, спільний календар, форма події,
  обидві модалки, auth, профіль, запрошення, мобільна версія. Валідація форм, фільтри календарів/типів, пошук з хедера,
  стан подання в URL. Наступний крок — бекенд: auth → calendars → events, потім заміна моків на `src/api/*`.
